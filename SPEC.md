# Draftkeeper — техническое задание (финальная версия)

## Платформы
- Одно веб-приложение, открывается в браузере
- Работает на Mac, Windows, Android, iOS — без установки отдельных программ
- PWA: можно "установить" на главный экран телефона / как приложение в Chrome
  на компьютере, работает офлайн

## Хранение данных
- Локально на каждом устройстве (localStorage / IndexedDB в браузере)
- НЕТ облачной базы данных, НЕТ backend, НЕТ авторизации
- Никакого администрирования хостинга базы данных не требуется

## Перенос данных между устройствами
- Только вручную: экспорт проекта в JSON-файл на одном устройстве →
  перенос файла любым способом (почта, облачная папка, AirDrop, флешка) →
  импорт на другом устройстве
- Функция уже реализована в прототипе (кнопки "Экспорт" / "Импорт")
- Автоматической синхронизации нет и не планируется — осознанное решение,
  чтобы не зависеть от облачной инфраструктуры и её обслуживания

## Хостинг
- Только статические файлы (HTML/CSS/JS) — например Netlify, Vercel,
  GitHub Pages, Cloudflare Pages, все бесплатно
- Никакого сервера базы данных, который может "заснуть" или требовать
  наблюдения — сайт отдаёт файлы, вся логика работает в браузере пользователя

## Проекты
- Несколько параллельных проектов (романы, фанфики)
- Переключение, создание, переименование, удаление
- Импорт/экспорт в JSON (также служит способом переноса между устройствами)

## Главы
- Текст главы + отдельные авторские заметки
- Порядок глав (можно менять)
- На телефоне — полноэкранный редактор
- История версий: ручное сохранение версии (кнопка "Сохранить версию" +
  опциональное смысловое название), список версий с датой, сравнение
  выбранной версии с текущим текстом через подсвеченный diff
  (добавленное — зелёным, удалённое — красным зачёркнутым),
  возможность откатиться к версии целиком

## Персонажи (расширенная карточка)
- Внешность (описание + фото — сохраняется как base64 внутри localStorage/JSON)
- Характер / психология
- Биография / backstory
- Цели и мотивация
- Речевые особенности
- Арка развития — заметка "что с персонажем" в каждой главе, где он участвует
- Связи между персонажами (тип отношения + описание): враг, друг, родственник и т.п.
- Привязка к сюжетным веткам (в каких участвует)

## Сюжетные ветки
- Иерархия (родительская/дочерняя ветка)
- Описание
- Список персонажей, участвующих в ветке

## Таймлайн
- События с датой/периодом (текстовое поле, не строгий формат)
- Автосортировка

## Заметки / лор / исследования
- Свободные заметки: заголовок + текст
- Теги — пользователь сам создаёт и редактирует (не фиксированный список категорий)
- Фильтрация по тегу (облако тегов сверху, клик — фильтр)
- Связь заметки с конкретными персонажами / главами / ветками
  (может быть несколько связей у одной заметки, без ограничения количества
  заметок на один элемент — глава может быть связана с любым числом заметок)
- Используется для: результатов исследований (например, поездки/референсы),
  лора мира, ценностей/мотивов книги, случайных идей
- Действия с заметкой: создать, редактировать (заголовок, текст, теги),
  удалить, привязать/отвязать к персонажам/главам/веткам
- Поиск по тексту заметок (не только по тегам)
- Сортировка списка заметок (по дате создания, по дате изменения, по алфавиту)
- Прикрепление изображений к заметке (референс-фото, сохраняются как base64,
  как и фото персонажей)

## Резервное копирование и импорт
- Локальный импорт/экспорт JSON — уже реализовано (кнопки "Экспорт" / "Импорт"),
  основной способ переноса данных между устройствами вручную
- Резервное копирование в Google Drive — дополнительная страховка на случай
  потери данных на устройстве:
  - Один раз: авторизация через Google (OAuth, доступ только к файлам,
    созданным самим приложением — drive.file scope, без доступа к остальному Диску)
  - Кнопка "Сохранить в Google Drive" — по явному клику отправляет точную
    копию данных проекта (тот же JSON, что при обычном экспорте) в файл
    на Google Drive пользователя. Никакой автоматики — только по нажатию
  - Кнопка "Загрузить из Google Drive" — по явному клику находит последний
    сохранённый файл-бэкап и восстанавливает из него данные
  - Показывать время последнего сохранённого бэкапа рядом с кнопками
  - Не требует своего сервера — OAuth и запись/чтение файла происходят
    прямо из браузера пользователя (Google Identity Services)

## Экспорт в Word (.docx)
- Цель: подготовить текст к публикации на платформах или отправке издателю —
  это отдельный экспорт от служебного JSON (тот нужен для переноса/бэкапа
  данных приложения, этот — готовый читаемый документ)
- Два режима:
  - Экспорт одной главы отдельным .docx файлом
  - Экспорт всего романа/проекта одним .docx файлом (все главы по порядку)
- Форматирование — стандартный издательский формат:
  - Шрифт Times New Roman, 12pt
  - Двойной межстрочный интервал
  - Поля страницы 1 дюйм (2.54 см) со всех сторон
  - Отступ первой строки абзаца (без дополнительного интервала между абзацами)
  - Каждая глава начинается с новой страницы, название главы — заголовок
  - Нумерация страниц
- Не включает служебные данные приложения (заметки, версии, связи персонажей
  и т.п.) — только сам текст глав, как в чистовике
- Выбор папки для сохранения: там, где браузер это поддерживает
  (Chrome/Edge на компьютере — через File System Access API), при экспорте
  показывается системный диалог "Сохранить как..." с выбором папки.
  В браузерах без такой поддержки (Safari, мобильные браузеры) — обычное
  скачивание в папку загрузок браузера/системный диалог "Сохранить в..."
  (зависит от настроек самого браузера/ОС, не приложения)

## Интерфейс
- Desktop: боковая панель + основная область (уже сделано в прототипе)
- Мобильный: отдельная адаптивная раскладка — нижняя навигация,
  полноэкранные формы, крупные зоны нажатия

## Технологии
- Frontend: HTML/CSS/JS (без фреймворка)
- Хранение: localStorage (данные проекта — единый JSON-объект)
- PWA: manifest.json + service worker (офлайн-кэш статики и данных)
- Хостинг: любой статический (Netlify/Vercel/GitHub Pages/Cloudflare Pages)
- Файловая структура на сегодня:
  ```
  draftkeeper/
    SPEC.md                 — это ТЗ
    GOOGLE_DRIVE_SETUP.md    — инструкция по настройке Google Cloud
    src/
      index.html
      style.css
      app.js
  ```
  (main.js и package.json от прежнего варианта с Electron удалены —
  Electron в проекте больше не используется; supabase_schema.sql тоже
  удалён как избыточный — все поля персонажа уже перечислены текстом
  в разделе "Персонажи" выше)
