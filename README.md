# Draftkeeper

Инструмент для писателей: главы, персонажи, сюжетные ветки, таймлайн, заметки.
Работает как обычный сайт в браузере (и как PWA — можно "установить" на телефон
или компьютер), все данные хранятся локально на устройстве в localStorage.
Никакой базы данных, сервера или регистрации не требуется.

Подробное техническое задание — в [SPEC.md](SPEC.md).

## Структура проекта

Публиковать нужно только содержимое папки `src/` — это готовый статический
сайт (HTML/CSS/JS), без сборки, без `npm install`, без шага компиляции.

```
draftkeeper/
  src/            ← вот эту папку и выкладываем на хостинг
    index.html
    style.css
    app.js
    config.js     ← сюда вписывается свой Google Drive Client ID (см. ниже)
    manifest.json
    sw.js
    icons/
    vendor/
```

## Проверка на своём компьютере перед публикацией

Открыть `src/index.html` напрямую двойным кликом (`file://...`) не подойдёт —
service worker (офлайн-режим) работает только через `http://` или `https://`.
Проще всего поднять локальный сервер:

```bash
cd src
python3 -m http.server 8080
```

и открыть `http://localhost:8080` в браузере.

## Публикация — уже сделано (GitHub Pages)

Ничего покупать не нужно — ни домен, ни тариф. Выбрали GitHub Pages вместо
Netlify/Vercel осознанно: репозиторий уже под полным контролем (свой аккаунт,
можно в любой момент перенести код куда угодно — это просто статические
файлы), и GitHub как площадка исторически стабильнее венчурных хостингов.

- Репозиторий: https://github.com/RM-dev21/draftkeeper (публичный — так
  устроены бесплатные GitHub Pages, сам код открыт, но в нём нет ничьих
  личных данных, только код приложения)
- Живой сайт: **https://rm-dev21.github.io/draftkeeper/**
- Деплой автоматический: при каждом `git push` в ветку `main` GitHub Actions
  (файл `.github/workflows/deploy-pages.yml`) публикует содержимое папки
  `src/` заново — руками ничего заливать не нужно

Как это было настроено (на случай, если понадобится повторить для другого
проекта или на другом аккаунте):

1. Установлен `gh` (`brew install gh`), выполнен вход: `gh auth login --web`
2. Одноразово выданы права `workflow` (нужны, чтобы пушить файлы в
   `.github/workflows/`): `gh auth refresh -h github.com -s workflow`
3. `git init`, `git add -A`, `git commit`
4. `gh repo create draftkeeper --public --source=. --remote=origin --push`
5. Включены Pages с источником "GitHub Actions":
   `gh api repos/RM-dev21/draftkeeper/pages -X POST -f build_type=workflow`
6. Дальше всё запускается само по push в `main`

### Альтернативы (если вдруг захочется без Git)

<details>
<summary>Netlify — перетаскиванием папки, без аккаунта на GitHub</summary>

1. Зайти на https://app.netlify.com и зарегистрироваться (можно через Google-аккаунт)
2. На главной странице найти область "Deploy manually" / перетаскивание файлов
3. Перетащить туда папку `src` целиком
4. Через несколько секунд Netlify выдаст рабочий адрес вида
   `https://случайное-имя.netlify.app`
</details>

<details>
<summary>Vercel — аналогично, тоже без Git</summary>

1. Зайти на https://vercel.com и зарегистрироваться (можно через GitHub/Google)
2. New Project → Deploy (там же есть перетаскивание папки, без Git)
3. В качестве корня проекта указать папку `src`
4. Vercel выдаст адрес вида `https://имя-проекта.vercel.app`
</details>

## После публикации

- **Google Drive бэкап** (если нужен): зайти в Google Cloud Console и в
  настройках OAuth Client ID добавить `https://rm-dev21.github.io` в список
  "Authorized JavaScript origins" — подробности в
  [GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md). Client ID вписывается в
  `src/config.js` один раз.
- **Установка как приложение**: открыть сайт на телефоне — браузер предложит
  "Добавить на главный экран" (Android/Chrome) или это можно сделать вручную
  через "Поделиться" → "На экран Домой" (iPhone/Safari). На компьютере в
  Chrome/Edge в адресной строке появится значок установки.
- **Перенос данных между устройствами**: только вручную — кнопки "Экспорт
  проекта (JSON)" / "Импорт проекта (JSON)" в интерфейсе. Автоматической
  синхронизации нет — это осознанное решение (см. SPEC.md).

## Обновление сайта после правок в коде

Просто `git add`, `git commit`, `git push` в `main` — GitHub Actions сам
пересоберёт и опубликует сайт по тому же адресу за 1-2 минуты. Проверить
статус деплоя можно на вкладке **Actions** репозитория.

Важный нюанс: в `src/sw.js` есть офлайн-кэш статики. После каждого пуша с
изменением файлов приложения нужно поднимать номер `CACHE_VERSION` в начале
`sw.js` — иначе у тех, кто уже открывал сайт раньше, браузер продолжит
показывать старую закэшированную версию вместо новой.
