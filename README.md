# Draftkeeper

Инструмент для писателей: главы, персонажи, сюжетные ветки, таймлайн, заметки.
Работает как обычный сайт в браузере (и как PWA — можно "установить" на телефон
или компьютер), все данные хранятся локально на устройстве в localStorage.
Никакой базы данных, сервера или регистрации не требуется.

Подробное техническое задание — в [SPEC.md](SPEC.md).

## Структура проекта

Публиковать нужно только содержимое папки `src/` — это готовый статический
сайт (HTML/CSS/JS), без сборки, без `npm install`, без шага компиляции.

```
draftkeeper/
  src/            ← вот эту папку и выкладываем на хостинг
    index.html
    style.css
    app.js
    config.js     ← сюда вписывается свой Google Drive Client ID (см. ниже)
    manifest.json
    sw.js
    icons/
    vendor/
```

## Проверка на своём компьютере перед публикацией

Открыть `src/index.html` напрямую двойным кликом (`file://...`) не подойдёт —
service worker (офлайн-режим) работает только через `http://` или `https://`.
Проще всего поднять локальный сервер:

```bash
cd src
python3 -m http.server 8080
```

и открыть `http://localhost:8080` в браузере.

## Публикация бесплатно

Ничего покупать не нужно — ни домен, ни тариф. Ниже три варианта, можно
выбрать любой один.

### Вариант 1 — Netlify (самый простой, без Git)

1. Зайти на https://app.netlify.com и зарегистрироваться (можно через Google-аккаунт)
2. На главной странице найти область "Deploy manually" / перетаскивание файлов
3. Перетащить туда папку `src` целиком
4. Через несколько секунд Netlify выдаст рабочий адрес вида
   `https://случайное-имя.netlify.app` — сайт уже открыт всем
5. Позже это имя можно поменять на более осмысленное:
   Site settings → Change site name

### Вариант 2 — Vercel

1. Зайти на https://vercel.com и зарегистрироваться (можно через GitHub/Google)
2. New Project → Deploy (там же есть перетаскивание папки, без Git)
3. В качестве корня проекта указать папку `src`
4. Vercel выдаст адрес вида `https://имя-проекта.vercel.app`

### Вариант 3 — GitHub Pages

Подходит, если данные уже лежат (или готовы лежать) в репозитории на GitHub.

1. Создать репозиторий на https://github.com (можно приватный или публичный)
2. Загрузить в него содержимое папки `src` (через `git push` или прямо
   через веб-интерфейс GitHub — кнопка "Add file" → "Upload files")
3. В репозитории: Settings → Pages
4. Source — "Deploy from a branch", Branch — `main`, папка — `/ (root)`
   (если файлы лежат прямо в корне репозитория, а не во вложенной `src/`)
5. Сохранить — через 1-2 минуты сайт появится по адресу
   `https://твой-логин.github.io/имя-репозитория`

## После публикации

- **Google Drive бэкап** (если нужен): зайти в Google Cloud Console и в
  настройках OAuth Client ID добавить реальный адрес сайта (например
  `https://имя-проекта.netlify.app`) в список "Authorized JavaScript origins" —
  подробности в [GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md). Client ID
  вписывается в `src/config.js` один раз.
- **Установка как приложение**: открыть сайт на телефоне — браузер предложит
  "Добавить на главный экран" (Android/Chrome) или это можно сделать вручную
  через "Поделиться" → "На экран Домой" (iPhone/Safari). На компьютере в
  Chrome/Edge в адресной строке появится значок установки.
- **Перенос данных между устройствами**: только вручную — кнопки "Экспорт
  проекта (JSON)" / "Импорт проекта (JSON)" в интерфейсе. Автоматической
  синхронизации нет — это осознанное решение (см. SPEC.md).

## Обновление сайта после правок в коде

Просто повторить деплой (заново перетащить папку в Netlify/Vercel или сделать
`git push` для GitHub Pages) — старый адрес сайта остаётся тем же.

Важный нюанс: в `src/sw.js` есть офлайн-кэш статики. После загрузки новой
версии файлов нужно поднять номер `CACHE_VERSION` в начале `sw.js` — иначе
у тех, кто уже открывал сайт раньше, браузер продолжит показывать старую
закэшированную версию вместо новой.
